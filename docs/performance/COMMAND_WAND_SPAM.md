# 指挥棒连点压力测试

[English](COMMAND_WAND_SPAM_EN.md)

## 每玩家 4 tick 冷却复测

同一 tick 由 32 人提交 1,024 次指令时，加入冷却后最多放行 32 次，原来放行 640 次。两轮的首次突发从 25.271／38.915 ms 分别降到 5.433／6.034 ms。后续突发从 2.478–3.640 ms 降到 0.527–0.897 ms。

| 场景 | 改前平均 MSPT A／B | 改后平均 MSPT A／B |
| --- | ---: | ---: |
| 空载 | 0.366／0.422 | 0.394／0.414 |
| 单人，每 tick 提交十次 | 0.394／0.477 | 0.410／0.412 |
| 32 人，每人每 tick 提交一次 | 0.678／0.677 | 0.485／0.565 |
| 32 人，每人每 tick 提交十次 | 0.593／0.622 | 0.455／0.510 |

在最后一组中，每轮 357 个采样 tick 均收到 114,240 条请求，放行数从 11,424 降为 2,784。复测使用下述同一机器和场景。每阶段预留 20 个无输入 tick，随后跳过 5 个以上的过渡 tick，再测稳定负载。前后两种实现各运行两轮，交替安排启动顺序。真实多人网络和复杂机械负载仍未包含在这次测量中。

## 加入冷却前的基线

模拟 32 名玩家持续连点时，每 tick 提交 320 次指令，服务端放行 32 次并拒绝 288 次。两次独立运行的平均整服耗时为 0.513–0.550 MSPT。32 人都攒满额度后同时下令，每次突发放行 640 次。两次运行的首个满额突发分别耗时 25.420 ms 和 24.679 ms，后续四次为 2.224–3.505 ms。实测峰值低于 20 TPS 的 50 ms 单 tick 预算。

## 方法与范围

- Windows，Ryzen 7 9800X3D，Java 21.0.6，Minecraft 1.21.1，NeoForge 21.1.235，2 GiB 堆。在两个独立的 GameTest 服务端世界上运行相同的当前 0.1.404 源码。每个持续场景每轮采样 357 ticks，记录 Minecraft 服务端 tick 耗时。
- 32 个模拟玩家在同一个已激活核心上测试右键坐标指令，目标为约 112 格外的已加载地形。使用实际指挥棒封包编解码器和服务端处理方法。源码检查确认请求超额时在射线检测前返回。
- 满额突发每轮三次。每次同一 tick 提交 1,024 次，放行 640 次。记录的耗时包含整个服务端 tick。
- 此测试范围为服务端指令处理、射线判定和限速。真实客户端网络排队、回包、复杂机器模块和模组包负载需要独立测量。
